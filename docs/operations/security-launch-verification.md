# Security launch verification

This document maps #718 to executable evidence. It records the frontend/Worker boundary; backend authorization remains backend-owned and any defect discovered by the live isolation suite must be fixed in a focused backend PR for human merge.

| Launch guarantee | Enforcement | Automated evidence |
| --- | --- | --- |
| Practice isolation | Authenticated URL context defaults to the active Practice. Every non-active Practice identifier is independently checked through Better Auth membership before Worker-owned data access. Backend-proxied resources retain backend authorization. | `tests/unit/middleware/practiceContext.test.ts`, `tests/unit/middleware/auth.test.ts`, `tests/e2e/security-isolation.spec.ts` exercise path, query, and body-derived identifiers for owner, client, and unauthenticated sessions. |
| Active Practice and revocation | Active Practice claims are only trusted for the exact matching Practice. Completed session and membership validations are not cached across requests, so backend revocation/removal is observed on the next request. | `tests/unit/middleware/auth.test.ts` proves same-Practice routing, cross-Practice remote verification, and next-request session revocation. |
| OAuth state and origin | MCP OAuth uses PKCE, a per-attempt state in session storage, exact state matching, validated internal return paths, the production callback `https://ai.blawby.com/oauth/callback`, and canonical backend resource `https://api.blawby.com/mcp`. | `tests/component/McpOAuthCallbackPage.test.tsx` rejects missing/tampered state and unsafe return paths; `tests/unit/services/mcpOAuth.test.ts` locks production callback/resource origins. |
| Bounded entry points | Auth, public intake/widget/bootstrap/geo, conversations/presence, AI intent/chat/assistant/generation, website extraction, vitals, activity, and analysis use one-minute limits. `CHAT_COUNTER` provides atomic counters; missing stores fail closed; 429 responses include `Retry-After` and a stable error code. | `tests/unit/worker/middleware/compose.test.ts`, `tests/unit/middleware/rateLimit.test.ts`, route-table tests, and strict Wrangler dry-runs. |
| Response protections | Worker responses carry API CSP, HSTS, frame denial, MIME sniffing denial, strict referrer policy, and permissions policy. Production CORS reads only the validated production origin allowlist and fails closed when absent. Pages CSP and headers remain defined in `public/_headers`. | `tests/unit/middleware/cors.test.ts`, `tests/unit/middleware/corsProduction.test.ts`, and the deployed health assertion in `tests/e2e/security-isolation.spec.ts`. |
| Internal surface closure | Worker debug/test routes require non-production plus `ALLOW_DEBUG`; the unauthenticated status/cleanup HTTP surface was removed; the engineer intake inspector remains behind both Better Auth and the documented email allowlist. Frontend debug routes render `App404` outside Vite development. | `tests/unit/worker/route-table.test.ts`, `tests/unit/worker/routes/adminIntakeInspector.test.ts`, production build, and deployed isolation E2E. |
| Sanitized failures | Unexpected and all 5xx failures return `Internal server error`, an opaque correlation ID in body/header, and no stack, exception message, or configuration details. Expected 4xx messages remain actionable. | `tests/unit/worker/errorHandler.test.ts`. |
| Dependency baseline | Better Auth client packages are aligned on stable 1.6.23; DOMPurify, Lodash, and transitive `qs` are pinned above their fixed versions. Backend server packages are upgraded separately by backend PR Blawby/blawby-backend#368 for human review. | `tests/unit/security/dependencyBaseline.test.ts`, package lock, and dependency audit. The remaining moderate OAuth resource-indicator advisory has no stable fix; backend `validAudiences` and MCP handler `audience` both bind to the canonical `/mcp` resource. |

The E2E suite uses the isolated owner/client launch fixtures and an impossible Practice UUID. It performs reads only; it does not touch production data or mutate another tenant.
